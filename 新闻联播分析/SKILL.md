# 新闻联播分析 Skill

## 一、目的

本 Skill 将《新闻联播》逐字稿处理成“先预览、后深入”的分析结果。

核心链路是：

```text
原文归档 → 每条新闻预览卡 → 主题匹配 → 回查原文 → 历史对比 → 趋势分析
```

新闻条目可以参考 `SKILL.md` 的元数据设计，但新闻条目不是可执行 Skill。本 Skill 也不拆成多个子 Skill。

## 二、触发场景

使用本 Skill 的场景包括：

- 抓取或整理《新闻联播》逐字稿；
- 生成当天新闻摘要；
- 比较当天与近30天、90天或一年内容的变化；
- 识别政策关键词、主题频次和措辞变化；
- 根据某个主题回查对应日期的原文；
- 判断政策从方向提出到部署、发布、试点或执行的阶段变化；
- 生成月度、季度或年度主题趋势。

如果用户只要求普通新闻摘要，不涉及政策、主题变化或历史对比，可以只使用摘要流程，不必加载全部长期分析参考资料。

## 三、数据根目录

优先使用环境变量 `NEWS_ANALYSIS_ROOT` 指向新闻数据目录。目录应包含：

```text
新闻联播分析数据/
├── 新闻联播原文/YYYY/MM/YYYYMMDD.md
├── 每日分析报告/YYYY/MM/YYYY-MM-DD_分析报告.md
├── 02-结构化索引/
│   ├── 预览卡/YYYY/MM/
│   ├── 详情证据/YYYY/MM/
│   ├── 月度统计/
│   └── 主题时间线/
├── 03-近30日变化追踪/
└── 06-运行日志/
```

如果没有设置 `NEWS_ANALYSIS_ROOT`，优先使用用户明确提供的数据路径，不得猜测或写入固定的个人绝对路径。

## 四、新闻预览卡

每天先为当天的每一条新闻生成一张轻量预览卡。预览卡采用 Skill 风格的元数据组织，但只是一条新闻的信息卡。

每张预览卡至少包含：

- `name`：新闻名称；
- `description`：一至两句话说明发生了什么；
- `triggers`：原始关键词、同义词、简称、产业和政策表达；
- `metadata.news_id`：日期加新闻顺序，例如 `20260819-06`；
- `metadata.topic_id`：跨日期的规范化主题；
- `metadata.date`、`metadata.order`、`metadata.category`；
- `metadata.policy_stage`：政策或事件阶段；
- `metadata.match_flags`：新主题、频率变化、措辞变化或阶段变化；
- `metadata.source_file`、`metadata.source_item`：原文定位；
- 简短的“为什么值得继续查看”。

预览卡不得复制整段逐字稿，不得在没有历史证据时直接给出长期趋势结论，也不得默认输出商机或投资建议。

推荐结构：

```markdown
---
name: 新闻名称
description: 一至两句话概括事实。
triggers:
  - 原始关键词
  - 同义表达
metadata:
  news_id: YYYYMMDD-NN
  topic_id: canonical-topic-id
  date: YYYY-MM-DD
  order: 1
  category: 经济产业
  policy_stage: 方向提出
  match_flags: []
  source_file: 新闻联播原文/YYYY/MM/YYYYMMDD.md
  source_item: 1
---

# 简要信息

事实摘要。

# 为什么值得继续查看

说明可能需要回查的历史问题。
```

## 五、命中后的深入处理

当用户问题命中预览卡的 `name`、`description`、`triggers`、`topic_id` 或 `metadata` 时，再执行深入处理：

1. 回读当前新闻的完整原文；
2. 根据 `topic_id` 和关键词检索历史预览卡；
3. 找到同一主题之前和之后最近几次出现；
4. 回读变化前后的关键原文片段；
5. 生成证据包，保留日期、路径、新闻顺序和原文引用；
6. 比较事实、主题、关键词、措辞和政策阶段；
7. 输出详情分析和待验证事项。

默认对比窗口：

- 前后7天：即时变化；
- 前后30天：近期政策节奏；
- 前后90天：季度趋势；
- 一年或更长：只使用月度、季度、年度索引和关键原文证据。

没有命中主题时，不要为了“完整”而读取整年的原文。

## 六、长期趋势和上下文控制

不要把90天或一年的全部逐字稿一次性传给模型。

使用分层输入：

- 当天分析：当天原文、近7至30天预览卡、命中主题的历史片段；
- 90天分析：3个月统计、主题时间线、变化节点原文；
- 一年分析：季度总结、月度统计、主题时间线、关键政策节点；
- 更长分析：年度总结和主题演变时间线，按需回查原文。

频次、首次出现、最后出现、连续出现和日期范围由程序统计。模型只解释统计结果，不凭记忆估算次数。

## 七、分析方法

重点观察：

- 新闻是否首次进入观察窗口；
- 报道顺序、篇幅和具体程度是否变化；
- 同一对象的关键词是否变化；
- 主题是否从方向表达进入部署、文件、试点、工程验证或实际执行；
- 新增了哪些地区、机构、企业、技术或政策工具；
- 过去连续出现的主题是否只是当天暂未出现。

严格区分：

- 原文事实；
- 与历史相比的可观察变化；
- 基于证据的解释；
- 尚待验证的推测。

## 八、不可违反的证据规则

- “近30天首次出现”不等于历史上首次出现；
- 当天未出现不等于政策取消或方向逆转；
- 单次参观、单次表态或单个关键词只能作为弱信号；
- 不使用脱离对象和语境的固定词语强弱词典；
- 不把新闻报道直接转化为投资、商机或买卖建议；
- 外交新闻中的各方说法要分别标注，不把单方表述当作已证实事实；
- 每个重要判断必须保留日期、来源文件和原文引用；
- 证据不足时明确输出“无法判断”。

## 九、默认输出

用户要求每日分析时，输出：

1. 今日总览；
2. 当天各新闻的精炼摘要；
3. 近30天新增主题；
4. 主题频率和报道重点变化；
5. 关键词和措辞变化；
6. 政策阶段变化；
7. 需要进一步核验的事项；
8. 分析限制。

默认不输出商机、投资标的和个人行动建议，除非用户明确要求启用独立的机会分析流程。

自动化调用时优先输出合法JSON；人工阅读时可输出Markdown。字段规范见 `references/data-contract.md`。
