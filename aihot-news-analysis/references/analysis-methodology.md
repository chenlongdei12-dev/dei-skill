# AIHOT 新闻分析方法论

## 两层输出

- **事实层**：输出发生了什么、谁做了什么、具体新增了什么、证据是什么。
- **分析层**：内部使用个人价值、企业需求、产业相关性、成熟度和证据强度筛选信息，并建立事件关联。

前期默认只输出事实层。积累足够历史之后，再在周报、月报或用户明确要求时输出边界、阶段和价值的综合分析。

## 事实优先

每条日报信息包含：

1. 事件事实：谁在什么时候做了什么。
2. 具体新增或改变：新功能、产品发布、合作、融资、政策、项目或产业动作。
3. 范围和状态：是否测试版、是否已上线、可用对象、地区、套餐和权限限制。
4. 已报道结果：只写来源明确给出的数据、案例或执行结果。
5. 证据与限制：提供 AIHOT 阅读页和原始来源，标注发布方陈述、单一案例或证据不足。

不要用“能力提升”“降本增效”等抽象词替代事实细节。例如“推出仪表盘”应写清它查看哪些数据、能下钻到什么粒度、谁可以用，以及当前是否为 Beta。

## 筛选标签

以下标签用于内部排序和长期建模，不默认展示为日报段落：

- `personal_relevance`
- `enterprise_relevance`
- `industry_relevance`
- `maturity_stage`
- `evidence_level`

优先保留有明确新增变化、真实工作流、可量化结果或 AI 产业影响的事件。纯底层实现、重复报道和没有事实支撑的夸张判断可以排除或合并。

## 跨事件关联

先将每条信息整理成事件卡片：行动主体、作用对象、动作、能力或问题、成熟度阶段、约束、时间、地区、来源和证据等级。

寻找以下关系：

- 延续：同一产品、公司或项目的后续动作。
- 迭代：过去能力扩展到新对象、新渠道或更高权限。
- 产品化：研究或演示变成 API、应用、连接器或部署方案。
- 工作流延伸：从回答问题推进到执行邮件、文件、代码、客服或运维。
- 竞争或替代：不同主体解决同一个任务、成本问题或平台入口。
- 约束或回应：一个事件暴露成本、安全、能源、可靠性等约束，另一个事件回应它。
- 结果反馈：过去的产品或方法出现新的用户、效率、成本、失败或安全结果。
- 结构类比：不同领域呈现相同演进方向，但没有因果证据。

关联等级：

- `direct`：来源明确引用、延续或宣布。
- `structural`：存在清晰结构关系，但不能写成直接因果。
- `analogy`：只有趋势相似，只作为弱线索。

没有可靠关系时输出“暂无可靠历史关联”。

## AI 边界和成熟度

从六个边界追踪 AI：

- 能力：能完成哪些任务。
- 可靠性：错误率、可验证性和人工批准要求。
- 连接：能否读取和操作邮箱、文件、代码和业务系统。
- 成本：调用、部署、存储和人工复核成本。
- 领域：能否进入药物、机器人、安全等专业领域。
- 安全：权限、隐私、合规和高风险能力限制。

主题阶段使用：

`研究出现 -> 产品发布 -> 用户可用 -> 工作流试点 -> 有结果案例 -> 规模化扩展`

单次演示和发布方口号只能标为早期信号。阶段判断需要正式发布、可用入口、真实案例、量化结果或规模数据。

## 周报和月报

AIHOT 普通 items API 只保证 24 小时和 7 天窗口。月报必须使用本地每日快照，不能临时假设远端接口提供未经保证的 30 天历史。

周报和月报关注：

- 事件之间的关联和阶段迁移。
- AI 从研究、产品、可用工具到真实工作流的变化。
- 能力、可靠性、系统连接、成本、专业领域和安全边界。
- 普通人可用范围与企业需求之间的桥梁缺口。

不要从单条新闻推导确定趋势、投资结论或购买建议。
